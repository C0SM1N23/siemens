\chapter*{Scope and reading guide}
\addcontentsline{toc}{chapter}{Scope and reading guide}
\markboth{Scope and reading guide}{}

Three blocks are documented here: the RV32I CPU, the programmable interrupt
controller, and the machine timer. They are delivered together because the
interrupt path only makes sense as a whole, but the PIC is a self-contained IP
block with its own register interface and is documented as one
(Part~\ref{part:pic}).

Three other blocks appear in the surrounding system --- a multi-channel DMA
engine, a dual-port SRAM, and the interconnect --- and are \emph{not} part of this
delivery. They are described only where the CPU or PIC has to interoperate with
them, and nothing in this document should be read as documenting them.

\paragraph{How statements are backed.} Requirements and design intent come from
the two feature specifications and the project's own requirement tags
(\texttt{REQ1}--\texttt{REQ12}, \texttt{D1}--\texttt{D27}, and the PIC's
\texttt{D-*} tags), all of which also appear as comments in the source. Behaviour
comes from the RTL. Where a section states what the hardware does, the file it was
read from is named in the margin or in the text. Verification results come from
the two simulation flows and are quoted only where a run produced them.

\paragraph{What changed in revision 2.0.} Two behavioural changes were made to
the RTL, both of which close a gap between the delivered hardware and this
document rather than adding a feature. First, every sequential element in the
delivery is now reset; previously a small number of flops --- two AXI
response-code flags, the interrupt controller's nesting-stack arrays, and
several pipeline and command payloads --- were left unreset on the argument that
a valid bit made them unobservable. The response-code flags were in fact
observable, on the bus, as X. Chapter~\ref{ch:reset} states the new policy, its
cost, and the reset value of every register. Second, the bit positions this
document has always described as reserved in \reg{SRCx\_CONFIG} and
\reg{ESCALATION\_CFG} were being stored and read back rather than hardwired to
zero; they are now masked on write. Both changes were found by the verification
work described in Chapter~\ref{ch:verifplan}, and both are covered by tests that
have been shown to fail against the previous revision.

\paragraph{Assumed background.} The reader is expected to know RV32I and normal
RTL practice; the base instruction set is not re-explained here. AXI4-Lite
\emph{is} explained, in Section~\ref{sec:axiprimer}, because the bus is where the
integration surface of these blocks lies and because the rest of the document
refers constantly to its handshake rules. That section covers the protocol only
as far as is needed to follow what this implementation does with it.
