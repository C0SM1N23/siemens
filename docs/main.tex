\chapter*{Scope and reading guide}
\addcontentsline{toc}{chapter}{Scope and reading guide}
\markboth{Scope and reading guide}{}

Three blocks are documented here: the RV32I CPU, the programmable interrupt
controller and the machine timer. They are delivered together because the
interrupt path only makes sense as a whole; the PIC is nonetheless a
self-contained IP block with its own register interface and is documented as one
(Part~\ref{part:pic}). The multi-channel DMA engine, the dual-port SRAM and the
interconnect are \emph{not} part of this delivery, and appear only where the CPU
or the PIC has to interoperate with them.

\paragraph{How statements are backed.} Requirements and design intent come from
the two feature specifications and the project's requirement tags
(\texttt{REQ1}--\texttt{REQ12}, \texttt{D1}--\texttt{D28}, and the PIC's
\texttt{D-*} tags), which also appear as comments in the source. Behaviour comes
from the RTL, and the file it was read from is named. Verification results are
quoted only where a run produced them.

\paragraph{Implemented and validated are separate claims.} Parts~\ref{part:cpu}
to \ref{part:integration} describe what was built, read from the source of the
baseline named on the title page. Part~\ref{part:verif} describes what was
demonstrated, and Section~\ref{sec:valscope} states how far each demonstration
reached: which value spaces were swept exhaustively, which were sampled at their
boundaries, and which saw only the values the directed program happened to use.
Where the evidence is thinner than for its neighbours, the text says so.

\paragraph{Assumed background.} RV32I and normal RTL practice are assumed; the
base instruction set is not re-explained. AXI4-Lite \emph{is} explained, in
Section~\ref{sec:axiprimer}, because it is the integration surface of all three
blocks --- but only as far as is needed to follow what this implementation does
with it.
