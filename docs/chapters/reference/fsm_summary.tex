\section{CPU trap state}

Two flags in \file{cpu\_top.v} track where the core is with respect to a trap.
They are separate because they answer different questions.

\toprule
\textbf{Flag} & \textbf{Purpose} \\
\midrule
\sig{in\_irq}      & Set when an \emph{interrupt} is taken, cleared on \sig{MRET}. Gates
  \sig{cpu\_irq\_eoi}, so an \sig{MRET} closing a synchronous trap does not pop a PIC

\section{Why so little sequential control}

The design pushes work into combinational logic qualified by a valid bit rather
than into state machines. Three consequences follow, and they are visible
throughout the earlier chapters:

\begin{itemize}[nosep]
  \item The hazard unit needs no states because every decision is a function of
        the current cycle, gated by \sig{s2\_advance}.
  \item The PIC resolver needs no states because priority resolution is a pure
        function of the request vector, the configuration and the stack top.
  \item The AXI slave needs no explicit state because ``what has arrived so far''
        is exactly two flags.
\end{itemize}

The one place a real state machine earns its keep is the LSU, where a write has
three independent channels and the response must not be accepted before the
address phase completes. Even there the state register only distinguishes read
from write; per-channel progress is tracked separately, which is what keeps a
future AXI4-Full extension additive.
