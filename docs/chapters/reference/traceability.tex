\chapter{Requirement and design-decision traceability}
\label{ch:trace}

The project distinguishes two kinds of item, and so does this matrix.
\textbf{Requirements} (\texttt{REQ\#}) are behaviour the specifications fixed;
there was no choice to make, only compliance to achieve. \textbf{Design
decisions} (\texttt{D\#}, and the PIC's \texttt{D-*} tags) are points the
specifications explicitly delegated. Both sets of tags exist as comments in the
source, so any row can be located with a text search.

Status values used below:

\begin{itemize}[nosep]
  \item \textbf{Implemented} --- as specified, with verification evidence.
  \item \textbf{Implemented, deviation} --- built and working, but differing from
        the specification or from a standard in a way stated in the row.
  \item \textbf{Open} --- a system-level decision that is not the CPU's to make.
\end{itemize}
