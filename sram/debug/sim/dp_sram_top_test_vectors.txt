REM ==================== Section 2: Delayed Response Handshake ====================

REM ---- Test 2.1: delayed BREADY on INT_STATUS, adjusted scope ----
REM NOTE: the originally-planned scenario (inject a NEW real collision
REM while Port A's write to INT_STATUS is pending) is structurally
REM unreachable -- collision_det.v never sees register-region traffic
REM (a_mem_valid_bk is forced 0 while a_is_reg=1), and a collision needs
REM BOTH ports active on the memory region. This adjusted version confirms
REM the W1C clear applies promptly (visible from the first peek cycle) and
REM stays stable for the whole delayed-BREADY window, using Port B to peek
REM at INT_STATUS while Port A's write sits in WR_RESP. It does NOT
REM distinguish pre-fix from post-fix behavior (no re-triggering event is
REM injected), only functional correctness under an extended response window.

WRITE       A         004  00000003  -
RWCONFLICT  020       A    11111111  -

SLOWCLEAR   00000001  5    -   -

WRITE       A         004  00000000  -
